# The Weaver probe

One essay, one held tuple, the divergence read twice. Pre-registered at issue
#511 and the vehicle for the arms of issue #485: sigma the declared seed, q the
precision, d the device, and the cross-architecture cell across Ampere, Ada and
Blackwell. The k arm cites Run 4 of #485 rather than running, the rebuilt
engine's executable sections being identical to the installed ones.

One prompt asks for a long essay on Warren Weaver. It is run repeatedly under
one declared tuple with the declared seed drawn from a schedule and every other
field held. Two readings follow and are never folded into one number.

- **Reading one, the free run.** Two independent runs compared from the first
  position they differ, and how far they travel apart after it. The cascade.
- **Reading two, the re-fed run.** One run's token path fed back through
  another arrangement under the diagnostic binding, per-position distributions
  compared under identical context. The arithmetic. Entropies to the bit, and
  the ranked field by a truncated KL that reports the mass it saw.

```shell
python3 weaver_probe.py run    --config ARM.json
python3 weaver_probe.py refeed --config ARM.json --source DEPOSIT/runs/NAME [--as-arm OTHER.json]
python3 weaver_probe.py read   --deposit DEPOSIT
```

An arm's config names the stack, the agent, the artifact, the devices, the
seed schedule, the context capacity, the turn cap, and the field depth. `run`
writes one declaration per run with its own session and its own record, so
`derive` and `preload` read each record whole, and restores the agent's
standing declaration on exit. `refeed` derives the diagnostic declaration from a
source run's record, points it at the target arm's artifact and devices where
they differ, and drives the two-shell diagnostic flow. `read` computes both
readings from the deposit alone.
